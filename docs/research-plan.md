# QKAN-Mamba 研究与协作计划

状态日期：2026-10-21。机器可读计划由 `.ai-progress/workstreams/foundation/plans/research-cycle/v001.json` 管理。

## 工作方式

我们完成研究设计、代码实现和测试，交给合作者执行正式实验；合作者通过 GitHub 返回小型摘要和文件清单，通过认证文件交换服务返回大型产物。我们验收证据、分析总体结果和预先选定的 Case Study，更新门户、中文研究记录，再决定优化或提出新 Idea。

## 阶段与完成条件

1. **基础恢复**：核对代码差异，保存历史证据，建立进度、门户、交付工具；验证共享服务。数据未找回时明确报告，不能宣称恢复完成。
2. **数据核验**：五任务来源、许可、版本、标签、长度、独立划分、重复/泄漏、评估协议、文件哈希和可学习性证据齐全；只有 `qualified` 才能进入正式比较。
3. **相关工作与基线队列**：调研任务匹配的近期强方法、经典参考、简单参考以及相关量子与经典门控；记录论文/官方代码、协议可比性、纳入排除原因，冻结队列。
4. **基线交付**：固定源码和依赖，声明适配边界；验证前向、梯度、一步更新、模型选择、恢复、导出和样本轨迹。提供命令、预算、返回白名单。
5. **合作者运行基线**：先环境预检，再完整数据运行；按共同协议比较，单独记录硬件和耗时，审计失败和不确定性。
6. **Idea 设计与实现**：根据基线不足形成可证伪假设；保留参数匹配经典控制；实现与理论复核后通过小型预检。
7. **Idea 正式验证**：先完整数据单种子；根据预先约定的决策门槛进入 3 种子，关键结论按需要扩到 5 种子。短时排错不替代完整训练。
8. **分析、归档、迭代**：核对交付完整性，分析总体指标、配对差值和 Case Study；区分实现错误、无任务收益、归因不明；更新结果、日志、解释，选一个优先下一步。

## 交付契约

- 每个实验指定 Git 提交、配置、数据版本/哈希、种子、环境、硬件要求、资源预算和唯一运行目录。
- 长于一小时的任务默认具备经过新进程验证的完整恢复能力；`latest` 与 `best` 分开，测试选定的最佳验证模型。
- `sample-trace.v2` 采集规则在实验前确定，配对方法用相同样本。目标仅在训练监督或评估允许的阶段访问。
- GitHub 只收经过检查的小内容（通常每文件不超过 1 MiB）；权重、原始日志、预测、完整张量和数据进入文件服务。
- 文件上传必须校验大小和 SHA-256。失败保留 pending 清单并非零退出，重试不得重训或覆盖不同内容。
- 计算完成、交付完成、科学假设是否成立、文档闭环分别记录。
