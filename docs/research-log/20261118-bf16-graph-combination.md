# 2026-11-18：BF16 与 Graph 的叠加测试交付

用户提出进一步测试当前 BF16 解析 K 偏置策略与 CUDA Graph 叠加。已有证据只分别测过 FP32 Graph 和 BF16 eager；它们之间的差距不证明 BF16 Graph 也快，不能直接把两个加速比相乘。

此次保持原 BF16 精度、原解析梯度／Adam 历史、dropout 0.1、micro16／logical128，只新增每文档独立的前反向 Graph。解析钩子包含主机观察，留在捕获之外；两份私有编码器梯度以固定次序、全新存储合并，保留共享 RNG 的前向串行规则，不额外加入编译或 micro32。

新增 `experiment.py diagnose bf16-graph`，绑定安全暂停后的最新 BF16 正式 checkpoint，而非历史 FP32 来源。顺序验证浮点／RNG／完整更新、独立进程连续2与1＋1恢复、ABBA×2完整更新耗时；正向收益还要求四组配对都为正。原检查点、状态、配置及两份已完成结果的哈希必须不变，报告成功或失败都自动回传；不允许静默 eager 回退后宣称 Graph 生效。

本地验证限于 QT2 的标准库和 fake 控制，不导入 torch／numpy／jax，不查询 GPU、不运行模型、不安装依赖。代码路径、父子启动、失败回传、数值拒绝、恢复与回滚属于本地交付证据；真实 CUDA 捕获、恢复、吞吐和显存仍待执行端。即使诊断通过，实际正式 worker 的组合接入也另需验证，不直接改 `graph=false`。

执行指令和试验后恢复原训练＋美化看板的命令见 `docs/baselines/bf16-graph.md`。本次未操作协作者进程。
