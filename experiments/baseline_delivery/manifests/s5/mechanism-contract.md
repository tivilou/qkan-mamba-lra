# S5 source-stage contract

Official commit 3c18fdb6b06414da35e77b94b9cd855f6a95ef17. strong-source-registry.json pins native Flax S5SSM, HiPPO/initialization helpers, SequenceLayer, StackedEncoderModel and training helpers. strong_sources verifies clean Git commit/file identities or complete offline snapshot identities, and imports actual modules. s5_encoder requires explicit eigenbasis, conjugate symmetry, direction, discretization, timescales, layer and normalization choices.

Keep complex-valued diagonal state, input/output matrices, bilinear/ZOH discretization and jax.lax.associative_scan. Preserve real-pair parameter representation and source parameter-group optimizer semantics. The official sequence model includes a Dense input encoder, normalization, residual/GLU/dropout choices; classification produces log-softmax, while the native Retrieval model uses its own four-feature MLP head. These differ from the project's common head and must not be silently mixed.

The common classification head declares float32 with JAX HIGHEST dot precision in its Flax Dense forward, independent source reference and JIT trace replay. Replay reconstructs the batch's pooling/pair features from full decoded encoder arrays, never from captured pooled/logits. The original rtol=1e-5 and atol=1e-6 checks remain required; no tolerance exception is granted. Source probe also compares compiled logits to independent head reconstruction from that forward's encoder outputs. The official encoder's operators and precision defaults are preserved.

Status: native task/training/full-state/trace adapters and explicit isolated environment recipes are implemented; current actual-device evidence is pending. All required source, recovery and trace commands are combined in scripts/run_formal_readiness.sh. A committed reviewed admission policy binds this contract and the declared adaptation diff; runtime certificates are generated only after all gates and verified return pass. Import/constructor success alone never certifies the model. Source-author score equivalence is not claimed.

Checkpoint transport uses NumPy leaves, but live TrainState must use JAX device leaves in both fresh and resumed processes with identical explicit dtypes. Restore is followed by exact serialization roundtrip validation before training. Compare all declared state fields using s5_recovery.py; return only bounded field paths, element counts and aggregate differences if unequal. The gate remains exact and never admits a numerical tolerance for S5.

Source probes and training/recovery children must start with --xla_gpu_deterministic_ops=true --xla_gpu_autotune_level=0 and CUBLAS_WORKSPACE_CONFIG=:4096:8. The pinned XLA GPU compiler expands indeterministic scatters under this flag; no replacement encoder, custom gradient or tolerance relaxation is permitted. Runtime metadata binds the settings, and actual-device exact recovery remains the admission authority.

Opt-in adaptive-memory execution changes only physical microbatch partitioning under the same logical update budget. It defines a distinct numerical trajectory; it does not establish equivalence to the fixed-policy run or inherit its checkpoint admission. Source-pinned mixer equations and precision remain unchanged. See `docs/baselines/adaptive-memory.md` for rollback, throughput search, bounded recovery coverage and pending hardware validation.

Adaptive execution also uses a validated logical-batch staging cache, one CPU batch of prefetch, device-side per-update statistics, five-second advisory status writes and reusable GPU rollback buffers with CPU fallback (immutable candidate state for S5). Positive throughput gains have no percentage floor and require multiple confirmation windows. FP32 and the logical update budget are unchanged; device behavior and speedup remain unverified for this revision.

Explicit migration may fork a paused admitted31639c0 full-state checkpoint into a separate adaptive suite after new source/recovery/trace admission and a fresh native-worker zero-update restore/roundtrip check. Only revision/contract and controller metadata change; scientific configuration is locked. The fixed prefix and adaptive continuation retain lineage and must not be reported as an uninterrupted fixed-policy baseline. Original checkpoints are preserved; native migration remains executor validation.
